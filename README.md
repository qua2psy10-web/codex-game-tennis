# BASELINE — Tennis

PC・スマホのブラウザで遊べる、コンピューター対戦の 3D テニス試作です。
自動移動で打球に集中するか、手動移動で自分でボールを追うかを選べます。

## 起動

Python 3 があれば、追加インストールやビルドは不要です。

```bash
cd /workspace/codex-game-tennis
python3 -m http.server 8000 --bind 0.0.0.0
```

ローカル開発ではブラウザでポート 8000 のサーバーを開きます。
`npm start` でも同じサーバーを起動できます。
トップ画面で男子か女子と「自動 / 手動」の移動モードを選び、「試合を始める」を押してください。
WebGL 2 対応の Chrome / Edge / Firefox / Safari が必要です。

## 操作

| キー | 動作 |
| --- | --- |
| Space | サーブのトス → もう一度押して打つ。ラリーでは合図に合わせて返球 |
| ← / → | 押している間、左右のコースを狙う。離すとセンターに戻る |
| ↑ / ↓ | 深い球 / 浅い球を選ぶ（次に変更するまで維持） |
| W / A / S / D | 手動モードで前 / 左 / 後ろ / 右へ移動。キーを離すと停止 |
| Esc | 一時停止 / 再開 |

サーブは緑のタイミングゾーンで打ちます。2回のフォルトで失点します。
ラリーでは「今、SPACE！」の合図と選手の足元の緑のリングが打てる目安です。
相手も自動で追いかけて返球しますが、左右に振るとミスを誘えます。
画面上の薄い緑のリングは、狙っている着地点です。
タブを離れると試合は自動で一時停止します。
移動モードは一時停止画面でも変更でき、スコアはそのまま続きます。
試合の速さも一時停止画面で「ゆっくり / 標準 / 速め」から選べます（0.85 / 1 / 1.12倍）。
球速と移動、サーブのタイミングが一緒に変わるので、まずゆっくりで感覚をつかめます。
ラリーでは打球できる直前の約0.12秒の入力を受け付けます。手動移動ではボールの近くにいる必要があります。
手動モードではボールに近づく必要があります。自分のサーブ中はトスから打球まで位置を固定します。

### スマホ・タッチ操作

- 手動移動：左のスティックを上下左右にドラッグ。指を離すと停止。
- 打球：右の大きなボタン。サーブは「トス」→「サーブ」の2回タップ。
- コース：「左 / 中 / 右」をタップすると選んだコースを維持。
- 奥行き：「深め / 浅め」ボタンで切り替え。
- 移動と打球を2本の指で同時操作できます。自動移動ならスティックは不要です。
- 縦向き・横向きに対応。画面回転やタッチのキャンセルでは移動入力を解除します。

打球ボタンは指を置いた瞬間に反応し、指を離すまで待ちません。
小画面ではボールを少し大きく表示し、タッチ端末の描画解像度を抑えて負荷を減らしています。

## 初版の仕様

- 男子 / 女子を選択し、同性のコンピューターライバルとシングルス。
- 1セット：6ゲーム以上かつ2ゲーム差で勝利。6–6で7点以上・2点差のタイブレーク。
- 通常ゲームは 0 / 15 / 30 / 40、デュース、アドバンテージあり。
- ゲームごとにサーブ交代。タイブレークは最初の1点、その後2点ずつ交代。
- 青いハードコート、背後視点、通常ショット、ボールのバウンド・ネット・アウト判定。
- やさしい AI、打球合図、自動 / 手動移動。入力・シミュレーション・描画を分離。
- 関節付きGLBキャラクター4人とスイング・走行・サーブ・得点ポーズ。選手選択には承認済み画像を使用。
- PC のキーボードとスマホの2本指操作に対応。縦横のタッチ画面用レイアウトあり。

## 音・演出・キャラクター

サーブ、返球、バウンドの音を分け、ポイント獲得と勝敗には短いメロディーを加えています。
ボールの短い軌跡、打球時のリング、着地の波紋、得点時のガッツポーズを表示します。
動きを減らす端末設定では軌跡・波紋・文字の拡大演出を抑えます。
4人のウェア、襟、袖、顔の細部、男子ライバルの肩幅、女子ライバルのカーリーヘアを描き分けています。

承認画像を基に、Blenderで制作した4人のオリジナルGLBモデルを試合に読み込みます。
骨格は15関節で、身体のメッシュは関節付近で重みを混ぜ、肘・膝などを曲げます。
選手選択の「3Dキャラクターを見る」では参考画像とモデルを並べ、回転・拡大と5種類の動きを確認できます。
読み込みに失敗した場合はメッセージを表示し、従来の試作モデルでプレイを続けます。
モデルは人体の比率、服装、髪型を反映したゲーム用の初版です。画像と同じ写真品質の肌・髪・布の質感にはまだ達していません。
動きはJavaScriptで関節を制御しており、モーションキャプチャやBlenderのアニメーションクリップは使用していません。
オンライン対戦、複数難易度、球種の使い分けは未実装です。

## 検証

Node.js で実行：

```bash
npm test
npm run check
```

テスト対象は得点、デュース、セット終了、タイブレークのサービス順、フォルト、
ネット・アウト、ラリー、自動サーブ、一時停止、操作による1セットの勝利・敗北です。
手動移動の速度・斜め移動・移動範囲・打球距離・モード切り替えもテスト対象です。
33件のテストには打球入力の猶予・期限切れ・距離制限と試合速度の切り替えも含みます。
4人のGLBについて、ファイル構造、必要な骨格、各頂点のスキンウェイトも検証します。
肘の前向きの屈曲、手の頭上への上がり方、膝の後ろ向きの屈曲を実際の骨格で検証します。
腕の動きで腰・太もものメッシュが引き伸ばされないことも4人分のGLBで検証します。
ブラウザの選手選択、サーブ、返球、WASD の押下・解放、ポーズ、説明、終了確認を Playwright で検証しています。
Chromium のタッチエミュレーションで2本指操作、指の解放・キャンセル、縦向き390×844と横向き844×390を確認しています。
実機の iPhone / Android や Safari での操作性・性能の確認はまだ行っていません。

## 構成

- `index.html`：選手選択、HUD、ダイアログ
- `tennis/main.js`：画面状態、音、描画ループ
- `tennis/controls.js`：キーボード、スティック、複数のタッチ入力
- `tennis/game.js`：描画に依存しない試合ルール・物理・自動移動・AI
- `tennis/scene.js`：Three.js コートと選手の配置
- `tennis/athletes.js`：GLB読み込み、関節の動き、リソース解放
- `tennis/character-viewer.js`：3Dモデルの回転・拡大・動きの確認
- `tennis/athlete-fallback.js`：読み込み失敗時の代替モデル
- `tennis/assets/`：承認済み4人のキャラクター画像
- `tennis/assets/models/`：4人のGLBモデルと編集用Blenderファイル
- `tools/build-athletes.py`：モデルの再生成スクリプト
- `tennis/tests/`：ルールとシミュレーションの回帰テスト
- `tennis/vendor/`：Three.js 0.180.0 と MIT ライセンス。同梱して外部 CDN への実行時依存を回避

GitHub Pages はリポジトリのルートを公開すれば動作します。

## モデルの制作・再生成

実行時は追加のインストールが不要です。モデルを編集・再生成する場合のみBlender 4.3以降を使用します。

```bash
blender --background --python tools/build-athletes.py
npm test
```

GLBと`.blend`を4人分再生成します。モデルの形状と材質はこのプロジェクトで制作したもので、外部の人物モデルは使っていません。
Three.jsのGLTFLoaderとBufferGeometryUtilsは同じ0.180.0を同梱し、ローカル相対インポートに変更しています。ライセンスは`tennis/vendor/THREE-LICENSE`です。
